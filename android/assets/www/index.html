QUÉ ES FORGE CORE STOCK

Un sistema de gestión completo que funciona dentro de tu teléfono

FORGE CORE STOCK junta lo que un almacén, un minimarket o un local de barrio necesita para vender y controlar mercadería, sin contratar un sistema mensual ni depender de internet. El corazón es un núcleo escrito en Rust con una base de datos SQLite local: cada producto, cada boleta y cada movimiento vive en el archivo del propio equipo.

Se maneja con el lector de código de barras del teléfono: apuntas la cámara al envase y el producto queda buscado o dado de alta en segundos. Además trae una wiki de productos y bases libres que completan nombre, categoría y ficha técnica de lo que vas cargando. Como los datos pueden viajar a SQLite y a la nube, el negocio sigue funcionando aunque se corte el internet y se puede respaldar o revisar desde otro dispositivo cuando vuelva la conexión.

Sin mensualidad El sistema vive en tu equipo. No pagas licencia por mes para vender.
Sin internet Vende, cobra y consulta stock aunque la red esté caída.
Rápido de operar Escaneas, vendes y la boleta sale sola, con IVA y correlativo.
Tus datos son tuyos Puedes respaldarlos, exportarlos o llevarlos a otro dispositivo.

           Conectar la base de InsForge
          
    
            
    La app ya sincroniza con InsForge a través de fabri-api.
              La APK nunca ve la cadena de Postgres: sólo un Bearer propio.
              Son cuatro pasos y se hace una vez.
    
            
      
              
    1. Creá el proyecto en insforge.app y copiá la cadena
                postgresql://… de Connect → Connection string.
      2. 
              
    2. Creá la tabla inv_productos: la primera llamada con
                accion: "asegurar" la crea sola, o pegá el SQL de abajo en el
                editor de InsForge.
      3. 
              
    3. Configurá Vercel (proyecto fabri-api) con
                INSFORGE_DATABASE_URL y FABRI_API_TOKEN, y redeployá.
      4. 
              
    4. En la app: Integración → Nube, URL https://fabri-api.vercel.app
                y el mismo token. Probá con el botón de abajo.
      5. 
            
    
            
    
              
    
                Variables de Vercel
                
              
    
              
    INSFORGE_DATABASE_URL=postgresql://usuario:clave@host:5432/insforge
FABRI_API_TOKEN=un-token-largo-y-propio
    
            
    
            
    
              
    
                Tabla en InsForge
                
              
    
              
    CREATE TABLE IF NOT EXISTS inv_productos (
  codigo       TEXT PRIMARY KEY,
  nombre       TEXT NOT NULL DEFAULT '',
  marca        TEXT NOT NULL DEFAULT '',
  categoria    TEXT NOT NULL DEFAULT 'abarrotes',
  unidad       TEXT NOT NULL DEFAULT 'unidad',
  costo        NUMERIC NOT NULL DEFAULT 0,
  precio       NUMERIC NOT NULL DEFAULT 0,
  stock        INTEGER NOT NULL DEFAULT 0,
  stock_minimo INTEGER NOT NULL DEFAULT 0,
  iva          INTEGER NOT NULL DEFAULT 19,
  proveedor    TEXT NOT NULL DEFAULT '',
  origen       TEXT NOT NULL DEFAULT 'manual',
  notas        TEXT NOT NULL DEFAULT '',
  ficha        JSONB NOT NULL DEFAULT '{}'::jsonb,
  actualizado  BIGINT NOT NULL DEFAULT 0,
  nube_ts      TIMESTAMPTZ NOT NULL DEFAULT now()
);

CREATE INDEX IF NOT EXISTS idx_inv_productos_categoria
  ON inv_productos (categoria);
CREATE INDEX IF NOT EXISTS idx_inv_productos_actualizado
  ON inv_productos (actualizado);

    Qué hace cada pieza
    
              
    La APK guarda en SQLite y marca los cambios con sync_ts.
                Sincronizar manda sólo los pendientes a fabri-api, que hace
                upsert por codigo en InsForge. Si no hay red, el lote queda pendiente
                y se reintenta solo.
    
              
    fabri-api es un proxy delgado en Vercel: valida el Bearer,
                habla con Postgres y devuelve JSON. La cadena de base vive sólo en sus variables
                de entorno, nunca en el teléfono.
    
              
    Si algo falla
    
              
      
                
    • 401: el token de la app no coincide con FABRI_API_TOKEN.
      • 
                
    • 500 / ECONNREFUSED: falta INSFORGE_DATABASE_URL o InsForge
                  pausó el proyecto por inactividad.
      • 
                
    • No aparecen los productos: revisá que la tabla se llame
                  inv_productos y que el redeploy de Vercel haya terminado.
      • 
                
    • Prefiero REST directo: usá
                  https://<app>.insforge.app/api/database/records/<tabla>
                  con Authorization: Bearer <anon-key>. El POST va con un array
                  y Prefer: return=representation.
      • 
              
    
              
    La guía larga, con el esquema completo y ejemplos, está en
                docs/INSFORGE.md del repositorio.
