Documento de ejecución

FABRI-CORE · Documento de ejecución

Cómo se construye FABRI-CORE de verdad: fases, dependencias, puntos de control y
artefactos verificables. Pensado para ejecutarse **desde el propio teléfono** y para que
cualquier persona (o agente) pueda retomar el trabajo sin leer todo el código.

Estado: **documentación y arquitectura listas; la app todavía no está escrita.**

Lo que sí existe hoy: el contrato funcional (spec), el sistema de diseño, los diagramas y

esta documentación.

---

0. Reglas de la casa (no negociables)

1. **No se afirma una función terminada hasta comprobarla.** Cada fase termina con un

artefacto verificable, no con "debería funcionar".

2. **Nunca** se matan ni reinician los procesos de OpenCode ni del sistema desde un agente.

3. **RAM antes que velocidad**: si no hay memoria, se espera (guardián) en vez de renderizar.

4. **El spec manda**: si el JSON cambia, se regenera la documentación (`docs/generar-docs.py`).

5. **Nada de datos inventados**: si una fuente no respondió, la UI dice *no disponible*.

2. Dependencias para compilar desde el teléfono



Nada de esto viene con Ubuntu o PRoot: hay que bajarlo (y el disco del teléfono va al 93 %,


así que se planifica por fases).



2.1 Toolchain base



QuéVersiónTamaño aprox.Notas


JDK17 (LTS)~300 MB`apt install openjdk-17-jdk` (en proot) o descarga directa de Temurin.


Android SDK (cmdline-tools + platform-tools + build-tools 34 + platform 34)—~1,2 GBDescargar por paquetes: `cmdline-tools`, `platform-tools`, `build-tools;34.0.0`, `platforms;android-34`.


Gradle8.x (wrapper)~200 MB con su distroEl wrapper baja solo: mejor dejar el `.zip` local y usar `--offline`.


Android NDK (solo si PRoot/SQLite propio)r26~1 GBOpcional: no hacerlo salvo que D1/D3 lo exija.





**Presupuesto de disco**: el build completo (SDK + NDK + Gradle + builds) pide **~6 GB


libres**. Con 14 GB disponibles y 207 GB usados, hay que:


    

  • borrar builds antiguos (`rm -rf app/build`) entre pruebas,
    • 

  • `GRADLE_USER_HOME` dentro de `/root` pero vigilado,
    • 

  • y no instalar el NDK si se puede evitar.
    • 



2.2 Compilar la APK desde el dispositivo
# 1) toolchain export ANDROID_SDK_ROOT=/root/android-sdk export JAVA_HOME=/usr/lib/jvm/java-17-openjdk-arm64 # 2) proyecto cd /root/fabri-core ./gradlew --offline assembleDebug #首 primera vez: sin --offline (descarga deps) # 3) instalar adb install -r app/build/outputs/apk/debug/app-debug.apk 



Si `gradlew` no puede con la RAM del teléfono: `GRADLE_OPTS="-Xmx1g -XX:MaxMetaspaceSize=512m"`


y `--no-daemon --max-workers=1`.



2.3 Firmar (release)
keytool -genkeypair -v -keystore ~/fabri-core.keystore -alias fabri \ -keyalg RSA -keysize 4096 -validity 10000 # luego gradle con la config de release, y: apksigner verify --verbose app/build/outputs/apk/release/app-release.apk 



La clave **no** se versiona: vive en el dispositivo y en el backup del usuario.

3. Ejecutar el backend Go (dentro o fuera del APK)



OpciónCómoCuándo


**A. Proceso local en el teléfono**Binario Go compilado con `GOOS=android GOARCH=arm64` y ejecutado por la app vía `app_process`/execSi D3 pasa la prueba.


**B. Proceso en Termux/proot**El servicio corre en el proot y la app habla por **loopback** (`127.0.0.1:8787`) con un token de sesión en almacenamiento privado**Recomendada** mientras D3 no esté resuelto: reutiliza lo que ya funciona en el equipo.


**C. Sin backend**La app habla directo con el CLI de OpenCodeSi el resto no necesita el grafo en vivo; se declara el límite.





**Regla de seguridad**: el canal va por loopback con un token aleatorio por instalación,


guardado en `EncryptedSharedPreferences`, y se valida en cada request.

3. Datos y recuperación



    

  • **SQLite** es la fuente de verdad. `PRAGMA journal_mode=WAL`, `foreign_keys=ON`.
    • 

  • **FTS5**: se comprueba en runtime (`sqlite_compileoption_used('ENABLE_FTS5')`). Si no está,
    • 

  la app usa un índice inverso propio sobre `document_chunks` y **la UI lo declara**.


    

  • **Embeddings**: tabla `embeddings` (modelo, dimensiones, vector) ligada a `document_chunks`.
    • 

  La búsqueda vectorial **solo aparece activa** si hay embeddings utilizables.


    

  • **Fusión híbrida**: textual (BM25/FTS5) + vectorial (coseno) con pesos configurables y
    • 

  **procedencia obligatoria** en cada hit (`documento`, `fragmento`, `tabla`, `mensaje`).


    

  • Se distingue explícitamente: **coincidencia textual** ≠ **similitud semántica** ≠
    • 

  **razonamiento del modelo**. La UI etiqueta el tipo de cada coincidencia.



---



4. Agente



    

  • El agente es **OpenCode** invocado por una interfaz documentada (CLI por loopback en el
    • 

  teléfono, servidor en escritorio).


    

  • Cada sesión persiste en `agent_sessions` + `messages` (con `provenance` y referencias).
    • 

  • El chat muestra: estado de ejecución, herramientas invocadas, y **qué Knowledge se
    • 

  recuperó** antes de responder (para que se pueda auditar).


    

  • Interrupción: cancelar la tarea deja la tarea en estado reanudable (`tasks` + `task_events`).
    •
